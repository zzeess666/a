## 案例分析笔记

### 案例 1：两款3.5分有线耳机的差评拆解（2025年8月，wearesellers）

**背景**：
- Amazon Basics ($9.99, 174评论) vs LUDOS ($12.99, 215评论)
- 评分都是 3.5，差评率都约 30%
- 如果只看这几个数字，会认为两款差不多

**关键发现**：
- Amazon Basics **死于耐用性**（23.3%差评：几天就坏/线断/麦克风失灵）
- LUDOS **死于佩戴**（26.8%差评：耳塞掉出来，不管什么尺寸都戴不住）
- **评分一样，死法完全相反**
- 反直觉：LUDOS 音质更好（48条好评夸音质），但因佩戴问题综合分最低

**颗粒度分析的价值**：
- 同样是"音质差"，拆开是三种完全不同的问题：
  1. 屏蔽/焊接的品控问题（静电噪音）
  2. 喇叭单元选型问题（声音发闷）
  3. 调音方向问题（低音弱）
- 同样"耳塞掉出来"，75%的人反映戴不住 → 小耳朵人群被整个品类忽视

**选品策略推导**：
- 打 Amazon Basics → 把**寿命做扎实 + 12个月保修**
- 打 LUDOS → **人体工学是命门**：外壳做轻、加耳挂、配备 XS 耳套
- **小耳朵人群**基本被整个品类忽视 → 潜在细分市场

**方法论（可复用）**：
1. 导出评论（AMZ Data / ReviewExporter / 第三方工具）
2. AI 批量打标（按痛点类型、严重程度、提及频率）
3. 聚类做对比（同类痛点合并，不同类痛点分开）
4. 颗粒度拆分（好评/差评都要拆，不是只拆差评）
5. 推导改品方向或竞争策略

**工具/成本**：
- API 成本：几块钱
- 时间：2-3小时/品类
- 核心不是工具，是**打标维度定义**（什么算痛点、噪音，颗粒度多细）

**重要心得**：
- 评论数量和评分是**表面指标**，不拆不知道死法
- 同样3.5分，死法不同 → 选品和竞品分析的依据完全不一样
- 好评也要拆（好评里的"噪音"：比如用户夸的点并不是核心卖点，说明产品没有击中真正需求）

## 案例 2：产品开发框架（2026-06，知无不言沙龙）

**来源**：亚马逊选品开发实战沙龙活动介绍
**热度**：被置顶75次/推荐23次/87发帖/397互动，3万浏览，56人关注

### 产品开发六阶段框架

1. **从经验判断到协同决策**，让产品开发更科学
2. **从用户需求到产品定义**，让差异化更精准
3. **从单品验证到矩阵布局**，让 SKU 更高效
4. **从流量竞争到价值创造**，让模式更适配
5. **从跟随热点到把握窗口**，让增长更稳健
6. **从数据分析到新品放量**，让流程可复制

### 核心观点

- 选品不是找能做的，是找到**不能做的理由**
- 选品要从"经验判断"升级到"数据+协同决策"
- 用户需求 → 产品定义 → 差异化 → 矩阵布局

## 选品方法论汇总（阶段一）

### 维度一：评论拆解

核心：
- 评分是表面，死法才是关键
- 同样3.5分，死法可能完全相反（耐用性 vs 佩戴）
- 颗粒度：同样"音质差"可能是3种完全不同的问题
- 好评也要拆（发现"噪音"——用户夸的点不是核心卖点）

方法：
1. 导出评论
2. AI批量打标（痛点类型/严重程度/提及频率）
3. 聚类对比
4. 推导改品/竞争策略

### 维度二：竞品分析框架

- BSR 排名 → 估算销量
- 评论数/评分分布 → 竞争程度
- 差评聚类 → 品类痛点
- 好评聚类 → 用户真实需求
